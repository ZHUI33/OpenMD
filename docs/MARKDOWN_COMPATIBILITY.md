# Markdown 兼容性与源码保真

OpenMD 的兼容性原则是：进入所见即所得模式不等于授权格式化整个文件。未编辑的
Markdown 源码是规范来源；可视化编辑器的序列化结果只用于定位实际发生变化的范围。

## 当前覆盖

`tests/fixtures/markdown-compatibility/` 保存真实兼容语料，覆盖：

- YAML Front Matter、GFM 表格、任务列表、脚注、引用式链接、自动链接和 GFM Alerts。
- 行内/块级公式、Mermaid、围栏代码块和原始 HTML 块。
- 转义字符、中文标点、emoji、组合 Unicode、空段落、连续/嵌套列表和超长行。
- LF、CRLF、混合换行以及相对、空格和中文图片路径。
- 以 `:::name … :::` 表示但尚未实现的扩展容器。

每个语料都执行未编辑的 `source → visual → source` 精确往返。单纯切换模式不会触发
`onChange`，因此也不会把标签页标记为已修改。

## 可视化编辑行为

- YAML Front Matter 显示为源码编辑区。OpenMD 不解析、求值或重排 YAML 键。
- 脚注引用可点击或用 Enter/空格跳到定义；指针悬停和键盘聚焦会显示纯文本预览。
- `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` Alerts 显示为可编辑提示块。
- 引用式链接保留 full、collapsed 和 shortcut 写法；定义的 URL 与可选标题可直接编辑。
- 尖括号链接、邮箱和 GFM 裸链接可点击。中文句末标点保留在正文中，不进入跳转 URL。
- 原始 HTML 只显示源码，不插入活动 DOM。脚本、事件处理器和危险协议不会执行。
- 已识别但暂不支持的扩展容器显示为“暂不支持的 Markdown”源码块，可原样编辑。

这些行为不会关闭 DOMPurify、CSP、外部链接协议白名单或 IPC 输入校验。Markdown 中的
危险 URL 仍保存在源码中供用户修正，但可视化 DOM 使用不可导航的安全地址。

## 精确保留规则

在未编辑的范围内，OpenMD 保留：

- YAML 的键顺序、引号和空白。
- 代码围栏字符、长度、信息字符串和代码内容。
- HTML 块的标签、属性和空白。
- `*`/`-` 列表符、`*`/`_` 强调写法等同义 Markdown 拼写。
- LF、CRLF、单独 CR 和混合换行。
- 尾随空格、空段落、Unicode 码点和用户输入的长行。

实现上，OpenMD 比较可视化编辑前后的规范化序列化结果，再把最小变化范围映射回原始
源码。`tests/source-fidelity.test.ts` 明确验证 YAML、围栏、HTML、同义标记和混合换行
不会因为另一段内容被编辑而重写。

## 不可避免的局部归一化

只有用户实际编辑的语法范围可能采用当前序列化器的规范写法：

- 新建或重构的列表通常使用 `-`，强调通常使用 `*` / `**`。
- 被编辑的 GFM 表格会补齐管线、单元格间空格和最短分隔线；对齐语义保持为
  `:---`、`:---:` 或 `---:`。
- 新建或重构的代码块使用反引号围栏。未触碰的波浪线围栏不会改变。
- 编辑 Alert 内容时会输出标准 `> [!TYPE]` 块引用形式。
- 一个被替换范围内部若原先混用换行，会采用该位置最近的换行风格；范围外换行不变。
- 在两个块之间插入新块时，序列化器可能补齐保证 Markdown 可解析所需的空行。

上述归一化只限于变化范围，并由 `tests/source-fidelity.test.ts`、
`tests/markdown-compatibility.test.ts`、`tests/table-feature.test.ts` 和
`tests/editor-mode-integration.test.ts` 固定行为。若需要逐字符控制某个复杂结构，请在
源码模式中编辑。

## 表格键盘与剪贴板

- `Tab` / `Shift+Tab` 在单元格间导航；最后一个单元格按 `Tab` 会新增数据行。
- 右键菜单可在当前单元格前后插入或删除行列，并设置左、中、右对齐。
- 选中矩形单元格区域后复制，会写入制表符分列、换行分行的纯文本。
- 粘贴 TSV 数据从当前单元格填充矩形区域；超出当前表格的值会被裁剪，不会暗中改变表格
  大小。
